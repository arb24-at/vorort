# γ · Content Generator

## Purpose and inputs

Write useful human service content from the approved bilingual blueprint. Read AGENTS, Project boundaries, the matching `<directory>-bp.md`, actual locale record and locale SEO evidence. Confirm site-wide and page approval/version; a historical draft or completed source task is not approval. Read the complete latest target immediately before editing through Drive.

## Authoring

- Create English first, then German with formal **Sie** and a natural small-team **wir** voice. Preserve shared meaning, scope and planned structure; write idiomatically, not sentence-by-sentence translation. Use each locale's genuine research and mark provisional coverage honestly.
- Make headings name real topics. Prefer normal sentences over slogans, strained metaphors and keyword lists. Start with recognisable situations, practical scope and useful reassurance before a prominent enquiry; deeper chapters should add new value after it.
- Make small jobs welcome. Explain existing-equipment checks, options and trade-offs without inventing prices, customers, guarantees, availability, credentials, unsupported repairs or access/recovery capability.
- Repeat a subject only at a different useful depth. Cut duplicated boundaries, repeated sales claims, filler introductions and FAQ answers which merely copy chapters. Length follows reader value, not a quota.
- Select only useful blocks. The Workshop is a reusable palette; it is not an instruction to include every paragraph, list, callout, image or table. Maintain a clear heading hierarchy and source order. Do not invent styling keys or put implementation instructions in public copy.
- Keep editable copy, metadata, alt text, CTA prompts and related references in validated records. Preserve actual routes, translation IDs, canonical/alternate links and real anchor targets. Check landing summaries against the page hero.
- Stay within the approved journey and interactions. If meaning/scope/journey needs a substantial change, revise the blueprint for review before dependent work. Add Design/Implementation for a genuine missing block or renderer; do not create a customer-only imitation of a shared recipe.

## Contact, media and SEO

Describe the actual form transport: preparing an email draft is not direct submission or a sent message. Never request credentials or claim booking/delivery without implementation. Use verified central contact facts. Request needed artwork in Media Queue with a complete standalone prompt; provisional references are not acceptance.

Support the owned primary intent and useful secondary topics naturally, without density targets, translated evidence or cannibalising adjacent services. Link real relevant destinations. Use concise, specific metadata; do not pursue device-shopping/DIY or unsupported repair terms simply for volume.

## Completion and handoff

Read back changed records. Report blueprint version, meaning covered, justified routine variations, recipe/block IDs, SEO evidence/gaps, media/form dependencies and unavailable verification. A source-complete content task can be checked while the separate QA task remains open. Use AGENTS for Git/evidence rules; do not manufacture approval or permanent completion of the page.
