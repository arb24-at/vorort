# δ · Design

## Purpose and inputs

Make content easy to understand and the page polished, distinctive and responsive. Read AGENTS, the approved page intent, canonical registry/guidance, shared renderers/styles and affected consumers. Astro/static-first is an implementation choice, not a limit on visual quality.

## Composition

Use meaningful information relationships, strong topic headings, typography, layout and accessible focus states. Vary pacing and block quantity around content; avoid uniform card grids, decorative technical diagrams, slogan headings and excessive vertical padding. Test desktop/mobile density together. Keep source/keyboard order meaningful when columns stack. Use restrained motion with reduced-motion support and never rely on hover/colour alone.

A section specimen shows possibilities. Select, repeat, reorder and omit supported blocks; optional intros/eyebrows need not be filled. Rich prose may be one focused paragraph or a deeper chapter. Named presentation variants belong in `src/design-system/presentation.ts` and shared styles, with generic Design Lab examples; avoid page-ID styling and arbitrary dimensions in copy.

## Design Lab and lifecycle

`Private Service Page` is a cross-service specimen gallery; the business Workshop remains a separate journey. Keep realistic generic specimens, useful context notes and explicit alternatives. Customer journeys and complete service copy live in production records, not duplicated Workshop websites. Approved Sections and usage derive from the registry/actual consumers.

Canonical section and block states live together in `src/design-system/section-recipes.ts`. Only Aykhan can promote an Experimental design. Blueprint approval permits specified page trials; it does not change lifecycle. A new block inside an Approved parent stays separately Experimental and visibly labelled. Unregistered proposals remain Proposed and unimplemented.

Compatible shared refinements retain IDs and propagate. Document contract/source, rationale and every affected consumer. Changes to meaning, required fields or essential behaviour need affected-consumer review before migration: preserve the approved predecessor, develop a new Experimental identity where material, obtain Aykhan's decision and migrate deliberately. Do not deprecate a predecessor still in intended use.

## Media and handoff

Use artwork only when it clarifies meaning. Follow the art family and responsive crop needs in Media Queue; generic illustrations must not imply customer evidence. Update existing requests instead of duplicating them. Each request has one acceptance checkbox, target, purpose/crops and a standalone prompt sufficient for a separate image Chat.

Review actual page hierarchy, form comfort, contrast, responsive layout and media crops. Record what was browser-checked versus source-only, and leave focused RV work when tools are unavailable. Design review does not approve service/legal facts or release.
